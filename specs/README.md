# TLA+ models

Each `<Name>.tla` models one protocol of the node, and `<Name>.cfg` sets its
small constants and the properties that TLC checks. Run all of them with
`mise run tla`, or one with `sh scripts/tla.sh <Name>`. Each action in a
model names the function that it models. When you change that function,
change the model in the same commit.

| Model | Code | Checked properties |
|---|---|---|
| `DirectInvite` | `invites.rs`, `join_and_apply` in `access_groups.rs`, `import_bundle` and the contact functions in `direct.rs`, `PolicyEngine::admit`, `check_group` | A call that failed leaves no grant; one `sign_direct_invite` call runs at a time, so failed calls leave nobody in the group; a returned line whose grant is live admits its person unless the owner took them out of the group; the host admits a request only from an endpoint that the owner invited, with a claim signed for that endpoint, so a copied line gives nothing; the caller keeps only an authorization for its own endpoint; one contact name for one endpoint; a valid contact's name stays with its endpoint; each invite call ends (liveness) |
| `Admission` | `a2a_transport.rs`, `proof/admission.rs`, `PolicyEngine::admit`, `admit_with_replay`, `own_ids` and `cancel_if_owned` in `aether-store/src/tasks.rs` | A task's owner is the authenticated endpoint, which had a live grant and a group membership; one task for each endpoint and idempotency key; a refused, replayed or changed frame changes nothing; a nonce stays in the replay table until it expires; the queue stays within its limits, with one per-peer limit for each endpoint, so two endpoints under one name share nothing; a task ID that another endpoint used does not refuse a caller, and one endpoint has one task for a task ID that it sent; no answer shows another endpoint's task; only the owner cancels; an honest caller with access gets its task in (liveness) |
| `ExecutionLease` | `NodeStore` lease functions, `SchedulerContext` in `proof/scheduler.rs`, `Agent::cancel` and `EarlyCancels` in `agent.rs` | A lease row exists only while a task is leased or running; a turn starts at most once for a task; a live turn's task is running, cancelled, or `unknown_result`; a cancel that an earlier run left does not stop a turn; every cancel reaches the turn (liveness) |
| `ConnectedAgent` | `agent/connected.rs`, `EarlyCancels` in `agent.rs`, `protocol/agent-socket` | An open task ID belongs to a running turn on that connection; a task goes only to the attached connection, and only its agent's answer is taken; an answer comes only after the task was sent; a turn ends once; no agent, no task sent; a cancel never reaches the agent before its task; a cancel before the start cancels the turn, and no cancel is kept after its turn ended; no turn waits on a connection that is over; every turn ends with its time limit, and a turn with a cancelled honest agent stops (liveness) |
| `EventPaging` | `events_page`, `task_progress` and the event writers in `aether-store/src/tasks.rs`, `A2aTransport::handle`, `request_with_polling_on`, `follow` in `outbox.rs` | Event sequences have no gap and never change; a page is the ordered run after the caller's cursor; a page says "no more events" only at the end of the journal; the state and the page are from one instant; the cursor never moves back; a `node request` or an outbox attempt that stops with an answer has every event up to the one that ended the task; an ended task lets the caller stop (liveness) |
| `Outbox` | `outbox.rs`, `sent_tasks` store functions, host admission | The host keeps one task for each sent task; an answer comes only from the host; a task that the host runs never shows as failed after a replay; an attempt whose lease another process claimed records nothing; an ended task does not change; each task ends (liveness) |
| `HubInvite` | `hub_sync.rs`, `hub_membership.rs`, `admin_ui/hub.rs` workers, `server/lib/aether_hub` | A grant only for an approved row and its first endpoint; no grant for a blocked endpoint; one live grant for each approval, also when the store fails; a kept line belongs to the approval it was signed for; the caller keeps only lines that it accepted; an honest hub delivers an accepted invite (liveness) |
| `ManagedRoster` | `managed_client.rs`, `directory_client.rs`, `control_service.rs`, `aether-store/src/{managed,directory,control}.rs`, `RosterClaims::verify` in `identity.rs` | A token makes one member; a roster row comes from a join event; a claim admits work only for a member that joined; with one control URL the roster is exactly the events up to the cursor; a revoke that the node applied stays, whatever spellings of the control URL it used; a cursor never moves back or skips; the caller uses only an unexpired record of the trusted key, its scope and the agent it asked for, also with an attacker directory; a record that was public before a revoke cannot be published again; a revoke reaches a node that keeps syncing, each cursor catches up, and directory events reach the node also past an expired or other-key record (liveness) |
| `PendingChange` | `admin.rs` (`Administration`, `check_live`, `settle`), `aether-store/src/admin.rs`, `admin_socket.rs`, the start replay in `node_builder.rs` | A high-risk grant or a capability is live or stored only after a UI action for that id and value; a workspace, a limit and the stored policy come only from a UI action, also through `UpdatePolicy` and a node start; when no request runs and no undo waits, the node and the store agree, also after a store write failed; a revoked grant stays out, also after a restart; a stale confirmation is refused, also when the process stopped before the node had the other change; each change that took effect has an `applied` audit record written no later than the change; an expired pending change never applies; each request ends (liveness) |
| `PactConsent` | `pact/`, `aether-store/src/pact.rs`, the dispatch recheck in `proof.rs` | One token for each device code; no token from a denied code; no task without a token; a failed approval leaves no grant; no task starts after its grant is revoked; an approved flow gets a token, and an admitted task ends (liveness) |

## Properties that are not checked

These properties are in the models but not in the `.cfg` files. The
comment above each one says why.

| Model | Property | Why |
|---|---|---|
| `HubInvite` | `GrantToTypedName` | By design, the hub resolves the invite name, so an attacker hub chooses it. |
| `HubInvite` | `KeptLineFromNamedHost` | By design, for an invite the caller takes the sender endpoint from the hub. A request checks the listing key. |
| `ManagedRoster` | `NoAdmitAfterServiceRevoke` | By design, a revoke reaches the node at its next sync. |
| `Outbox` | `OneAttempt` | Two processes can work on one task when an attempt takes longer than the 90 s `LEASE`. `NoStaleRecord` checks that the late attempt changes nothing. |
| `PactConsent` | `StartCovered` | A grant can expire between the dispatch recheck and `mark_running`. Expiry has no lock; `StartNotRevoked` checks revocation. |
| `PendingChange` | `StaleSeesRevoke` | By design, a revoke and a policy save do not change the revision. |
| `PendingChange` | `NoMcpRevival` | By design, a low-risk grant applies without confirmation, also for a revoked ID. |
